## Summary

Every change to the consensus rules goes through a public QIP with fixed minimum times: 30 days of review, 14 days of last call, 60 days on testnet and a mainnet release at least 90 days before the fork height. A CI check refuses pull requests that change consensus code without naming an accepted QIP or stating that consensus does not change.

## Motivation

After the mainnet launch the rules must be practically immutable. Changes must be visible, reviewed and announced long before anyone has to decide whether to run them, and an unintended change must be caught automatically.

## Specification

See [GOVERNANCE.md](../GOVERNANCE.md). The consensus paths are listed in `scripts/consensus-paths.json`; the check is `scripts/consensus-guard.mjs`.

## Security considerations

This QIP changes no consensus rule. It adds no key and no trust.
